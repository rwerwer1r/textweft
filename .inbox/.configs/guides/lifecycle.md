# Inbox Lifecycle

Inbox는 세션 간 연속성을 위한 임시 증거이며 제품·개발 정책의 정본이 아닙니다. 작업 중 필요한 만큼 생성·수정·리뷰·인계합니다.

## Promote Durable Knowledge

- 제품 동작 요구사항은 STDD 도메인 Spec으로, 공통 개발 규칙은 `docs/` 또는 root instruction으로, 실행 동작은 코드·테스트로 옮깁니다.
- 승격 후에도 작업 인계·재현·감사에 원본이 필요한지 확인합니다. 원본을 정본처럼 계속 갱신하지 않습니다.
- Workstate의 `active`·`blocked`·`handoff`·`complete`는 해당 작업의 진행 상태이며 개별 연구/리뷰 문서의 품질이나 승인 상태가 아닙니다.

## Retain or Archive

- 실제 작업이 끝나고 필요한 근거가 정본·PR·테스트·Git 이력에 남았는지 확인하기 전에는 삭제하지 않습니다.
- 미완료·차단·인계된 작업 기록과 필수 증거는 보존합니다.
- 원본이 더 이상 필요 없고 맥락을 재구성할 수 있으면 삭제할 수 있습니다. 원본 자체가 재현·감사·참조에 필요하면 `.inbox/archive/YYYY-MM-DD/`로 이동합니다.
- 보존 기간을 임의의 일수로 자동화하지 않습니다. 완료 여부나 보존 필요성이 불명확하면 유지하고 재평가합니다.
- 자동 cleanup, 상태만으로 완료 추론, `main` 직접 쓰기 권한은 없습니다.

## Safe Records

비밀·개인정보·자격 증명·민감 로그·전체 프롬프트/대화를 저장하지 않습니다. 최소한의 재개 단서, 실제 증거, 미실행 항목, 승인과 다음 행동만 기록합니다.
