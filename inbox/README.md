# Inbox

`inbox/`는 **비정본이지만 Git에 보존하는 협업 공간(Durable Artifacts)**입니다. 조사·계획·리뷰·검증·인계·진행 상태를 인간과 에이전트가 세션을 넘어 공유합니다. 제품 요구사항·설계·코드·테스트·권한의 정본을 대체하지 않습니다.

## Ownership and Routing

| 자료 | 관리 위치 |
| --- | --- |
| 프레임워크 동작·제품 목표 | 소스·테스트·[README](../README.md)·[GOAL](../docs/GOAL.md) |
| 에이전트 권한·절차 | [AGENTS.md](../AGENTS.md)·[개발 가이드](../docs/development/README.md) |
| 조사·임시 계획·리뷰·검증 증거·인계·작업 상태 | `inbox/` |
| 변경·승인 및 실제 검증 | GitHub 브랜치·PR·검사 결과 |

현재 OpenSpec은 설치하지 않았습니다. 구현 전 설계도 비정본 초안으로 인박스에 남길 수 있지만 확정된 지속 요구·결정은 소유 문서에 승격합니다. 인박스는 **사람↔사람, 사람↔에이전트, 에이전트↔후속 에이전트**를 위한 표면입니다.

## Layout and Naming

| 작업 | 디렉터리 | 진입 파일 |
| --- | --- | --- |
| 특정 PR/Issue 연결 | `inbox/github-<number>-<slug>/` | `001-workstate.md`, `002-review.md` 등 3자리 순번 |
| 번호 없는 연구·횡단 주제·일일 메모 | `inbox/YYYY-MM-DD/` | `HH-MM-<slug>.md` |

GitHub 번호는 패딩하지 않습니다. PR 번호가 생긴 뒤에도 기존 기록은 필요할 때만 옮기거나 연결하며, 같은 작업에는 **활성 workstate 파일 하나**를 사용합니다. Markdown 파일 자체가 진입점이고 보조 CSV/JSON 등이 필요할 때만 `003-<slug>/index.md` 같은 번들로 구성합니다.

## Frontmatter

**새로 작성하거나 수정하는** 인박스 Markdown 진입 파일에는 YAML frontmatter를 둡니다. 정책 문서 `inbox/README.md`와 수정하지 않은 과거 파일은 예외입니다.

```yaml
---
description: 작업 상태의 짧은 식별용 설명
updated: 2026-10-31T09:00:00+09:00
title: 선택 제목
tags:
  - status:active
---
```

`description`은 비어 있으면 안 되고 `updated`는 실제 수정 시점의 타임존이 포함된 ISO 8601 일시여야 합니다. `title`과 `tags`는 선택 사항입니다. 위 시각은 형식 예시일 뿐 실제 수정 시각을 대신하지 않습니다.

변경된 파일만 `npm run inbox:check -- inbox/github-2-example/001-workstate.md`로 검사합니다. `node scripts/check-inbox.mjs --stdin0`는 NUL 구분 경로 목록을 받습니다. **검사는 필수 메타데이터 형태만 확인**하며 일반 YAML 전체나 사실성을 검증하지 않습니다.

## Session Checkpoints and Recovery

세션은 갑자기 중단될 수 있습니다. 복원 가치가 있는 사소하지 않은 다단계 작업은 **첫 중요한 조사 사실·결정·구현 상태가 생긴 즉시**, 다음 긴 작업 전에 작업 브랜치에 체크포인트를 원격 저장하고 다시 읽습니다. 세션 끝에 한 번만 기록하지 않습니다.

- **위치:** PR/Issue 작업은 `inbox/github-<number>-<slug>/001-workstate.md`; 번호가 없으면 날짜 디렉터리를 사용합니다.
- **갱신:** 범위·중요 결정·구현·검증·리뷰 결과가 바뀌거나 장시간 작업·승인 대기·인계를 앞두고 같은 파일을 갱신합니다. 모든 도구 호출마다 기록하지 않습니다.
- **영속성:** 커밋·push 또는 원격 API 저장 성공 후 **같은 ref의 파일을 다시 조회**해야 보존됐다고 판단합니다. 로컬 파일·채팅·미커밋 diff·PR 본문만으로 보존을 주장하지 않습니다.
- **예외:** 간단한 질의·읽기 전용 점검·작고 한 번에 끝나는 수정에는 별도 파일을 강제하지 않습니다. 이 정책만으로 `main`에 직접 쓰거나 다른 저장소에 기록할 권한이 생기지 않습니다.

### Minimum Workstate

| 항목 | 포함할 정보 |
| --- | --- |
| **Goal / Scope** | 목표·수용 조건·제약·제외 범위 |
| **Location** | 정확한 저장소·브랜치/ref·PR/Issue |
| **Current state** | `active`, `blocked`, `handoff`, `complete` 및 남은 작업 |
| **Evidence** | 실제 반영된 파일/커밋, 수행한 검사·CI 결과, 미실행 검증 |
| **Next action** | 재개 직후 할 구체적 작업, 남은 결정·위험·정리 조건 |

긴 로그·원본 프롬프트·비밀·개인 식별정보·자격 증명·비공개 URL·민감 도구 출력을 기록하지 않습니다. 체크포인트는 승인·검증·정본의 대체물이 아닙니다.

### Resume

1. 정확한 저장소·ref·권한·적용 지침과 관련 PR·활성 workstate를 다시 확인합니다.
2. 체크포인트를 현재 파일·diff·CI·PR과 대조하며, **최신 원격 증거가 오래된 기록에 우선**합니다.
3. 이미 수행한 변경·비가역적 부수효과를 중복 실행하지 않고 남은 승인 작업과 검증 공백만 진행합니다.
4. 의미 있는 진척을 같은 파일에 원격 반영합니다. 모두 충족된 경우에만 `complete`로 바꿉니다.

이는 세션 자동 재시작이나 백그라운드 작업 지속을 제공하지 않습니다. 마지막으로 원격 확인된 시점 이후의 미확인 작업을 완료로 주장하지 않습니다.

## Retention and Security

완료된 기록은 PR에 요약하고 지속되는 결론만 정본에 반영합니다. 오래된 **완료** 자료는 사람의 리뷰를 거쳐 정리할 수 있으나 열린 PR·진행 중인 상태·필수 증적은 임의 삭제하지 않습니다. 자동 삭제·`main` 직접 수정은 허용하지 않습니다. 정본 문서는 이 정책 문서 외의 개별 인박스 산출물에 의존하지 않습니다.
