# Core Engine Architecture Decision

- **상태:** 채택(2026-11-02, 프레임워크 개발자 결정)
- **범위:** 장기 코어 언어 결정. 구현 착수·단계 전환·병합 승인은 포함하지 않음.

## Decision

Textweft의 **게임 실행 코어는 Rust로 구현**한다. 현재 TypeScript 프로토타입의 구현 방식과 코드 구조는 신규 코어 설계의 제약으로 삼지 않는다.

- 코어는 렌더러와 브라우저·Node.js 전용 API에 의존하지 않는 **headless** 게임 규칙 실행 계층으로 설계한다.
- 웹 플레이어는 코어 구현 언어를 노출하지 않는 별도 계층으로 구성한다. **TypeScript 웹 계층과 Rust→WebAssembly 어댑터는 현재 우선 설계 방향**이며, 구체적인 패키징·바인딩 방식은 추후 결정한다.
- 게임 제작자가 Rust를 작성·설치·컴파일해야 하는 구조를 기본 경험으로 강제하지 않는다. 공개 저작 계약과 SDK가 내부 구현을 추상화한다.
- 이미지(정적/외부 생성), SFX/BGM, 동영상 및 고급 2D 연출은 **게임 제작자가 선택할 수 있는 웹 호스트/에셋/렌더링 계층의 능력**으로 취급한다. Rust 코어에 미디어 재생 구현을 강제하지 않는다.
- MOD는 게임 개발자가 **활성화 여부와 확장 범위를 결정**한다. MOD 로딩·정합성·권한 경계는 초기 아키텍처에서 고려하되 모든 게임에 MOD를 강제하지 않는다.

## Rationale

AI 주도 개발에서는 Rust 컴파일러·타입·소유권 검사·Clippy의 피드백을 활용하여 일부 오류를 조기에 발견하고 엔진 내부 불변식을 명시적으로 설계할 수 있다. 엔진을 웹 UI에서 분리하면 실행 환경별 재사용도 유리하다.

이 결정은 **Rust가 게임의 정확성이나 AI 개발 생산성 향상을 자동 보장한다는 주장에 근거하지 않는다**. 게임 규칙의 올바름은 계약 테스트와 실제 실행 검증으로 확인한다.

## Research and Scope

멀티미디어·2D 표현·ComfyUI 연동·선택형 MOD를 포함한 권장 컴포넌트 경계 및 근거는 [Engine Architecture Research](architecture/engine-research.md)에 기록한다. 해당 문서의 라이브러리와 프로토콜 예시는 **설계 후보**이며 확정된 구현 약속이 아니다.

## P1에서 남은 결정

- 게임 정의 형식과 게임별 확장 규칙·스크립트 실행 모델
- Rust 코어의 공개 경계 및 명령/결과·오류·저장 데이터 계약
- WebAssembly 어댑터, TypeScript SDK, 브라우저 배포·초기 로딩 방식
- 네이티브 실행 지원 범위와 재현성·호환성 검증 기준

P0 개발 환경·하네스 → P1 MVP 설정 → P2 MVP 구현의 기존 우선순위는 유지한다. Rust 엔진 이식·개발 도구 추가·기존 프로토타입 제거는 이 결정만으로 실행하지 않는다.
