# Project Goal

Textweft의 목표는 **선택 중심 텍스트 게임을 콘텐츠와 실행 환경의 결합 없이 만들고, 실행하고, 확장할 수 있는 작고 신뢰할 수 있는 프레임워크**를 제공하는 것입니다.

이 문서는 프로젝트의 장기 지향점과 품질 기준을 정의합니다. 현재 구현·공개 API·완료 상태·일정의 정본은 아니며, 이를 확인할 때는 [README](../README.md), 코드, 테스트 및 해당 PR을 참조합니다.

## Goal

게임 작성자는 장면과 선택지를 선언형 콘텐츠로 표현하고, 게임만의 규칙이 필요할 때 TypeScript 훅을 명시적으로 연결할 수 있어야 합니다. 게임 실행은 렌더러에 의존하지 않아 같은 게임 정의를 CLI, 웹 또는 별도 인터페이스에서 소비할 수 있어야 합니다.

```text
YAML / JSON game content  +  optional TypeScript hooks
                         |
                    Textweft core
              scene · choice · state
              transitions · snapshots
                         |
               renderer-neutral view
                         |
                CLI / web / custom UI
```

작성 경험은 단순해야 하지만, 잘못된 선택·훅 오류·재개 과정에서 게임 상태가 조용히 손상되어서는 안 됩니다.

## Milestones

### 1. A small, renderer-neutral runtime

장면 진입, 현재 보기, 유효한 선택, 상태 전이 및 종료를 이해하기 쉬운 작은 핵심 계약으로 제공합니다. 핵심 엔진은 특정 UI 프레임워크·장르·호스팅 환경을 요구하지 않아야 합니다.

### 2. Declarative stories with explicit extensions

대부분의 분기는 YAML/JSON의 장면·조건·효과·경로로 작성할 수 있어야 합니다. 선언형 표현만으로 부족한 규칙은 등록된 TypeScript 훅으로 확장하되, 콘텐츠가 임의 코드를 암묵적으로 실행하지 않도록 경계를 명확히 유지합니다.

### 3. Trustworthy and reproducible transitions

같은 게임 정의·초기 상태·시드·선택 이력이면 재현 가능한 결과를 얻도록 설계합니다. 잘못된 선택, 존재하지 않는 목적지 또는 실패한 훅은 런타임 상태·이력·난수 진행을 부분적으로 확정하지 않아야 합니다. 훅의 외부 부수효과에는 별도의 명시적 계약이 필요합니다.

### 4. Portable, inspectable progress

게임 상태를 보존하고 재개할 수 있도록 스냅샷의 의미와 호환성 경계를 분명하게 합니다. 저장·복원은 숨겨진 장면 재진입이나 예기치 않은 효과 실행을 발생시키지 않아야 합니다. 영속 저장소와 버전 간 마이그레이션 지원 여부는 필요에 따라 별도 결정합니다.

### 5. A usable authoring and integration path

게임 작성자와 렌더러 개발자가 예제, 타입, 명확한 오류, 집중 테스트를 통해 계약을 이해할 수 있도록 합니다. 실제로 필요한 사용 사례를 통해 범용성을 확인하고, 새 기능의 도입보다 작은 핵심 계약의 이해 가능성과 검증 가능성을 우선합니다.

## Product Principles

- **Genre-agnostic:** 특정 세계관·전투·인벤토리 모델을 엔진의 필수 전제로 만들지 않습니다.
- **Data-first:** 설명 가능한 선언형 콘텐츠를 우선하고, 필요한 복잡성만 명시적 코드 훅으로 분리합니다.
- **Headless by default:** 게임 규칙과 화면 표현·입출력·호스팅을 구분합니다.
- **Deterministic where promised:** 시드 난수와 상태 전이의 재현성·원자성을 명시된 경계에서 지킵니다.
- **Portable state:** 실행 중 상태와 저장 가능한 상태의 의미를 안정적으로 설명합니다.
- **Small and testable:** 기능의 폭보다 계약의 일관성, 예측 가능한 실패, 유지보수 비용을 우선합니다.

원칙이 충돌할 때는 핵심 엔진의 정합성과 게임 작성 경험을 훼손하지 않는 **가장 작은 검증 가능한 설계**를 우선합니다.

## Not the Goal

Textweft의 초기 목표는 다음을 모두 포함하는 범용 게임 제작 플랫폼이 아닙니다.

- 특정 장르에 고정된 전투·인벤토리·퀘스트 엔진
- 내장 그래픽 렌더러, 비주얼 에디터 또는 호스팅 서비스
- 자유 텍스트 명령 파서나 AI 기반 이야기 자동 생성 서비스
- 임의 코드 실행을 허용하는 데이터 포맷
- 모든 게임의 영속 저장·동기화·세이브 마이그레이션을 책임지는 백엔드
- 안정된 공개 패키지/API를 이미 제공한다는 보장

이 항목들은 영구 금지 대상이 아니라 **핵심 프레임워크의 기본 책임으로 앞서 도입하지 않을 대상**입니다. 필요성이 검증되면 선택형 확장 또는 별도 계층으로 평가할 수 있습니다.
