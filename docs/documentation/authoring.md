# Documentation Authoring and Review

## Ownership

- 먼저 [문서 지도](../README.md)에서 가장 가까운 소유자를 찾습니다.
- 제품 목표, 아키텍처 결정, 실행 절차, 도구 설정, 세션 증거는 각자의 정본에 둡니다. 다른 영역에서는 링크로 연결합니다.
- 코드·테스트·실행 설정·외부 규격은 각자 사실의 정본입니다. 문서는 목적과 한계를 설명하되 같은 값을 별도로 유지하지 않습니다.
- 반복되는 독립 질문과 명확한 독자가 있을 때만 새 문서를 만듭니다. 단순히 길다는 이유로 나누지 않습니다.

## Progressive Discovery

| 독자가 아는 범위 | 경로 |
| --- | --- |
| 정확한 파일·소유자를 앎 | 직접 링크 |
| 주제 영역을 앎 | 가장 가까운 디렉터리 README |
| docs 전체에서 소유자를 모름 | [INDEX.tsv](../INDEX.tsv) |

- 진입점에는 선택 기준만 둡니다. 본문 요약이나 중복 규칙을 만들지 않습니다.
- 일반 문서는 제목과 [description](frontmatter.md)으로 언제 선택할지 설명합니다.
- 필요한 문서만 점진적으로 읽고, 관련 없는 모든 문서를 선로드하지 않습니다.

## Review

1. 대상이 정본 소유자인지, 라우팅에서 불필요한 홉이 없는지 확인합니다.
2. 결정·제약·순서·식별자·근거·예외와 실제 검증 상태를 보존합니다.
3. 중복 설명, 빈 섹션, 미사용 템플릿과 확정된 사실처럼 보이는 추측을 제거합니다.
4. 상대 링크와 `mise run docs:index:check`, `mise run lint:md`를 확인합니다.

## Structure

비교·책임·증거 수준에는 표를, 분기·의존·상태 전이에는 필요한 경우에만 Mermaid를 사용합니다. 같은 내용을 본문·표·그림에 반복하지 않습니다. 숫자형 진행도는 확인 가능한 분자·분모와 근거가 있을 때만 제시합니다. 문서의 짧음보다 전체 읽기·수정·유지 비용을 낮추는 것을 우선합니다.
