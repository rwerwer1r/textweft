# Engine Design Research

**상태:** P1 설계 제안(미확정). 현재 집중 범위는 [Project Goal](../GOAL.md)의 **텍스트·정적 이미지 웹 게임**이며, Rust 코어 언어 결정은 [Architecture Decision](../architecture.md)에 있다. 기존 TypeScript 초안을 신규 설계의 제약으로 삼지 않는다.

## Recommended Flow

```text
Game author / AI -> game definition + static image assets
                           |
                 validation / packaging
                           |
                    web player (TS 후보)
                  text, images, input, save
                           |
                     WASM adapter 후보
                           |
                     Rust headless core
                 rules, state, transitions
```

Rust 코어는 **명령을 받아 게임 상태와 표시용 결과를 계산**하고, 웹 플레이어는 **텍스트·이미지를 실제로 표시**한다. 이미지 바이너리를 코어 상태에 저장하지 않고 논리적인 에셋 참조를 사용한다.

초기 코어는 작은 모듈형 모놀리스로 시작하는 것을 권장한다. 개념적으로 게임 정의·검증, 세션·상태 전이, 저장·복원을 구분하되 처음부터 여러 플러그인·크레이트·범용 ECS를 만들지 않는다.

## Minimal Contracts to Decide

| 계약 | 확인할 내용 |
| --- | --- |
| 게임 정의 | 장면, 텍스트·화자, 선택지·분기, 조건·효과, 이미지 참조 |
| 실행 | 시작·선택·현재 보기, 유효성 검사, 오류 시 원자성, 재현성 |
| 표시 | 렌더러 중립 결과와 화면의 정적 이미지·텍스트 매핑 |
| 저장 | 게임/정의 버전, 진행 상태, 복원 가능성 |
| 제작 | AI가 이해할 수 있는 오류 위치·원인·수정 경로 |

게임 개발자의 자유도를 위해 별도의 게임별 규칙 확장 방식이 필요할 수 있으나, **구체적인 스크립트 언어와 훅 API는 아직 채택하지 않는다**. 명령·결과 데이터 구조 역시 P1에서 가장 작은 실사용 사례로 결정한다.

## Acceptance Scenarios

1. 텍스트만 포함한 게임에서 시작 → 대사 → 선택 → 분기 → 종료가 동작한다.
2. 같은 진행 과정에서 배경 또는 인물의 **정적 이미지**를 연결·표시·교체할 수 있다.
3. 잘못된 이미지 참조·분기·조건은 제작자가 이해할 수 있는 오류를 발생시킨다.
4. 같은 정의·초기 상태·시드·선택 이력은 동일한 게임 결과를 만들고, 실패한 전이는 상태를 부분 변경하지 않는다.
5. 저장한 진행을 복원해 같은 장면부터 계속 플레이하며, 복원 자체로 장면 효과를 다시 실행하지 않는다.

간단한 미연시를 **수용 테스트 사례**로 사용할 수 있지만, 엔진 내부에 미연시 전용 모델을 넣지는 않는다. 이 시나리오는 설계 검증 기준이며 구현 완료를 의미하지 않는다.

## Deferred

오디오·BGM, 동영상, ComfyUI 연동, Spine 계열 스켈레탈 애니메이션, 선택적 MOD는 현재 **구체화하지 않는다**. 해당 기능의 API·포맷·라이브러리·보안 정책·도입 일정도 미정이다.

우선순위는 [Development Guide](../development/README.md)의 **P0 → P1 → P2**를 따른다. 웹/WASM 기술 검토는 [wasm-bindgen](https://wasm-bindgen.github.io/wasm-bindgen/) 문서를 참고할 수 있지만 도구 선택과 실행 테스트는 별도 확인 대상이다.
