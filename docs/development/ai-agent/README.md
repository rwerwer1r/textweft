# Agent Governance

AI 개발 하네스의 설계 원칙과 판단 기준을 정의합니다. 권한·계정·승인의 정본은 [AGENTS.md](../../../AGENTS.md)이며, 이 문서는 새 권한이나 실행 절차를 부여하지 않습니다.

## Harness Design Principles

1. **총비용 최소화** — 토큰·컨텍스트·도구 호출·검증 시간·사람의 개입·유지보수까지 포함한 비용을 줄입니다. 필요한 자산과 검사만 선택하고 중복 지침·형식적인 작업을 피하되, 안전과 필수 품질을 비용 절감의 대상으로 삼지 않습니다.
2. **공통 계약, 런타임별 최적화** — 챗봇과 코딩 에이전트는 같은 목표·권한 경계·검증 기준을 따르지만 실행 경로는 구분합니다. 실제 도구와 상태 보존 능력을 확인한 뒤 각 진입점에서 해당 작업에 필요한 컨텍스트만 주입합니다. 실행할 수 없는 작업은 수행한 것으로 간주하지 않습니다.
3. **자율적인 목표 달성** — 승인된 범위에서 AI가 목표를 작업으로 분해하고 계획·실행·검증·자체 리뷰·PR 준비와 필요한 재계획을 주도합니다. 중요한 결정과 최종 승인 경계는 유지하며, 세션 종료 후 자동 실행을 보장한다고 가정하지 않습니다.
4. **세션 비의존적 연속성** — 대화 기억이나 특정 에이전트에 의존하지 않습니다. 의미 있는 변경 목적은 Conventional Commits 커밋으로 보존하고, 메시지에는 필요한 판단·검증 한계·후속 조건만 남겨 재개 단서로 삼습니다. 전체 진행 상태와 지속되는 결정은 정본·PR·Issue·[Inbox](../../../.inbox/README.md) 등 적절한 위치에 최소한으로 보존합니다. 재개 시 현재 원격 상태를 다시 확인합니다.
5. **검증 가능한 결과** — 목표와 수용 조건을 실제 변경·테스트·검증 근거에 연결합니다. 실행·CI·정적 확인·미실행을 구분하고, 자기 검토를 독립 리뷰로 포장하지 않습니다.
6. **위험에 비례하는 자율성** — 가역적이고 작은 작업에는 불필요한 승인 대기를 만들지 않되, 권한·기밀·제품 결정·비가역 작업은 명시된 게이트를 지킵니다. 상세 경계는 [AGENTS.md](../../../AGENTS.md)가 소유합니다.
7. **재현성과 단일 정본** — 다음 세션이나 다른 런타임에서도 같은 저장소 상태와 선언된 개발 환경으로 결과를 재구성할 수 있어야 합니다. 정책·절차의 중복 복사 대신 정본을 연결하고, 라우팅·생성 파일은 파생물로 취급합니다.

## Decision Boundary

| 작업 | 담당 |
| --- | --- |
| 범위 내 작은 코드·테스트·문서 변경, PR 준비 | AI 주도·검증 근거 보고 |
| 제품 방향·공개 API/호환성·보안·구조·외부 노출·중요 비용 | 프레임워크 개발자 결정 |
| 병합·릴리스·배포·권한 변경 | 명시적 승인 및 플랫폼 게이트 |

## Review Evidence

diff에서 **계약·회귀·보안·문서 불일치·검증 공백**을 점검합니다. 같은 모델의 반복 검토는 독립 리뷰가 아닙니다. 테스트·CI·정적 확인·미실행을 구분합니다.

제품 동작의 근거는 코드·테스트·[README](../../../README.md)입니다. 런타임별 진입은 [CHATBOT](../../../CHATBOT.md)과 [ROUTE](../../../.agents/route/ROUTE.md), AI 협업은 [Vibe Coding](../workflows/vibe-coding.md), 개발 절차는 [Routine Loop](../workflows/routine-loop.md), 환경·검사는 [개발 문서](../README.md)를 따릅니다.
