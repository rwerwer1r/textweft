# Routine Working Loop

복잡한 RPI 실행·재귀·재계획은 `mols-loops`가 소유합니다. 이 문서는 공통 확인·검증·인계만 소유합니다. 행동 변경 Work는 [Delivery](../../../.rulesync/skills/workflow-delivery/SKILL.md)의 테스트 우선 절차를 적용합니다.

1. **시작:** 저장소·계정·ref·권한·AGENTS와 필요한 Rule/Skill, 기존 PR·코드·테스트를 확인합니다.
2. **범위:** 수용 조건·제외 범위·검증 방법을 정하고 작은 Work 단위를 유지합니다.
3. **Spec/Test:** 행동 계약이 바뀌면 Change Spec delta를 작성하고 테스트를 먼저 설계·구현합니다.
4. **실행:** 독립 Work만 병렬 위임합니다. 각 Worker는 분리된 workspace와 파일 소유권을 가져야 합니다.
5. **검증:** 관련 mise 검사·테스트를 실행하고 실제 실행/CI/정적 확인/미실행을 구분합니다.
6. **리뷰·인계:** 계약 위반·회귀·보안·Spec/Test 불일치를 자체 리뷰하고 결과·근거·위험·필요한 결정을 남깁니다.

복잡한 다단계 작업은 첫 의미 있는 상태 이후 다음 긴/위험 단계 전에 [Inbox](../../../.inbox/README.md)에 최소 체크포인트를 원격 보존·재조회합니다. 도구 호출마다 기록하지 않습니다. 병합은 별도 승인입니다.
