# Vibe Coding Workflow

Textweft는 **바이브코딩(vibe coding)** 방식으로 개발하는 **게임 제작 프레임워크**입니다. 사람은 자연어로 목표·사용 경험·제약을 전달하고, AI 에이전트가 탐색·설계 구체화·코드·테스트·예제·문서·PR 작성까지 주도합니다. **바이브코딩은 검증하지 않은 코드를 그대로 수용하는 방식이 아닙니다.**

## Responsibilities

- **사람:** 제품 방향, 기대 경험, 우선순위, 중요한 제약과 결과 피드백을 제공합니다. 일반적인 파일·함수·테스트 설계까지 미리 작성할 필요는 없습니다.
- **AI:** 현재 소스와 계약을 확인하고, 자연어 의도를 관찰 가능한 수용 조건으로 구체화한 뒤 작은 변경 단위로 구현·검증·자체 리뷰합니다. 일상적 구현 판단마다 승인 질문을 반복하지 않습니다.
- **승인 경계:** [AGENTS.md](../../../AGENTS.md)의 저장소/계정 격리 및 보안·호환성·아키텍처·병합 승인 규칙을 그대로 따릅니다. AI의 구현 주도권이 사람의 최종 제품 판단을 대체하지 않습니다.

## Intent to Evidence Loop

1. **Intent:** 요청에서 대상 사용자, 기대 행동, 바꾸지 말아야 할 동작, 관찰 가능한 성공 조건을 정리합니다. 작은 요청에는 불필요한 양식이나 긴 사전 명세를 강제하지 않습니다.
2. **Ground:** 현재 ref의 공개 API·예제·관련 코드/테스트를 읽습니다. 없는 API를 만들어진 사실처럼 전제하지 않습니다.
3. **Slice:** 가장 작은 유용한 변경을 정합니다. 복잡한 작업은 간결하게 단계화하지만, 일상적인 세부 구현은 사람에게 다시 설계받지 않습니다.
4. **Build:** 구현뿐 아니라 필요한 회귀 테스트, 사용 예제, 문서를 함께 갱신합니다. 특정 예제 게임의 편의를 이유로 장르 특화 구조를 핵심 프레임워크에 하드코딩하지 않습니다.
5. **Prove:** 실행 가능한 관련 검사와 공개 사용 경로를 확인합니다. 실패와 미실행을 구별하고, 실제 실행하지 않은 명령이나 AI 시뮬레이션을 테스트 통과로 표시하지 않습니다.
6. **Challenge:** 변경 diff의 계약 위반·회귀·경계 사례·보안·불필요한 추상화·문서 불일치를 자체 리뷰합니다. 필요하면 작은 수정과 재검증을 반복합니다. 동일 에이전트의 재검토는 독립 리뷰가 아닙니다.
7. **Show:** PR에 **의도 → 변경된 동작 → 사용·검증 근거 → 미확인/결정 사항**을 기록하여 사람이 제품 방향을 판단할 수 있게 합니다. PR 생성은 병합 권한을 포함하지 않습니다.

일반 흐름은 [Routine Working Loop](routine-loop.md), 요청 단계의 제한은 [Workflow Selection](choosing.md)을 따릅니다.

## Vibe-Coder Experience Gate

프레임워크 **주 사용자는 바이브코더**로, 자연어로 텍스트 게임의 장면·분기·규칙을 설명하고 AI 코딩 도구와 함께 게임을 제작합니다. 게임 플레이어 또는 특정 게임 자체가 이 저장소의 주 사용자/제품은 아닙니다.

공개 API·저작 경험의 변경은 다음을 확인합니다.

- AI와 사람이 **공개 문서와 타입만으로** 장면·선택·상태·훅을 조합할 수 있는가?
- 자연어 요구 → YAML/JSON 정의 및 선택적 TypeScript 훅 → 실행 결과 확인 → 오류 수정까지 짧게 이어지는가?
- 타입·오류·예제가 잘못된 장면 ID, 선택, 상태, 훅을 고치는 데 충분한 정보를 주는가?
- 게임별 예외를 핵심 엔진에 누적하지 않고 공통 계약이나 선택형 훅으로 수용하는가?

관련 기능을 바꿨다면 최소한 하나의 구체적인 사용자 시나리오와 관찰 결과를 제시합니다. **실제 AI 코딩 도구를 시험하지 않았다면 AI 사용성을 실측했다고 주장하지 않습니다.** 예제 게임은 프레임워크 검증 자료이지 제품 출시물이 아닙니다.

## Verification and Handoff

가용 환경에서 `npm test`, `npm run typecheck`, `npm run harness:check`, 해당하면 `npm run example`을 수행합니다. 수행·실패·미실행·CI 보고를 구별하고, 개발 속도 때문에 검증·권한·사람 승인 절차를 우회하지 않습니다. 프롬프트 전문이나 대화 기록은 기본 보관하지 않고 재현에 필요한 최소 입력 조건·변경·실행 증거만 PR 또는 [인박스](../../../inbox/README.md)에 남깁니다.
